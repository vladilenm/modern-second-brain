# Синхронизация Notion со вторым мозгом

Дата: 2026-11-02. Схема согласована пользователем.

## Результат

Notion появляется в списке источников BrainBar, панели и MCP-поиска. Фоновый `brain sync`
забирает страницы и изменения каждые 15 минут. Одна страница, в том числе запись базы Notion,
становится одной записью `source="notion"`, `kind="document"` со ссылкой на оригинал.
Текст проходит существующую маскировку секретов, индексирование и пересказ настроенной моделью.

Охват — все доступные страницы workspace, включая обычные разделы «Личное»
и «Архив», со всеми вложенными страницами и базами.
Страница с названием «Архив» отличается от страниц, помещённых в корзину Notion.

## Способ подключения

Рекомендуется REST API с персональным токеном владельца workspace. Этот способ доступен
на бесплатном тарифе, подходит для локальных скриптов и использует права самого пользователя.
Токен хранится в macOS Keychain: service `brain-notion`, account `default`; значение не попадает
в Git, журнал, статус и сообщения ошибок. Коннектор только читает Notion.

Альтернативы:

- Внутренняя интеграция с правом Read content: можно ограничить доступ выбранными корневыми
  страницами, но каждую из них нужно открыть интеграции; поддерживается тем же коннектором.
- Экспорт Markdown: работает без API-токена, но требует повторного экспорта вручную.
  Для автоматической синхронизации не подходит.

Подключённый к этому чату Notion позволяет проверить структуру и отдельные страницы.
Он не предоставляет приложению Brain отдельный REST-токен для запуска через launchd.

## Алгоритм и данные

- Python 3.9, только стандартная библиотека; API version `2026-03-11`.
- Добавить `NotionConnector(ApiConnector)` в реестр и настройки с выключенным по умолчанию
  источником. Локально включить после проверки учётных данных.
- Начальное обнаружение через API search с пагинацией. Поиск не гарантирует полный перечень:
  найденные страницы обходятся через дочерние блоки, базы — через data sources и их query.
- Последующие запуски повторяют обнаружение, чтобы замечать страницы, которые открыли доступу
  позже, даже если у них старая дата изменения. Тела неизменившихся страниц не скачиваются.
- Содержимое страницы: заголовок, текстовые свойства записи базы и тело Markdown v2.
  Пагинация обязательна для списков. Для усечённого Markdown дочитываются доступные поддеревья
  из `unknown_block_ids`; недоступные ссылки не считаются прочитанным текстом.
- Стабильный `external_id` по UUID страницы. Даты создания и редактирования берутся из Notion.
  Одинаковый текст не создаёт дублей и не вызывает повторный пересказ.
- В `source_cursor` хранится версия импортированной страницы по UUID. Прогресс сохраняется
  вместе с пачками записей средствами существующего sync. Ошибка не продвигает версию
  непрочитанной страницы; следующий запуск повторяет её.
- Первая загрузка ограничена 100 новыми или изменёнными страницами за запуск. Очередь найденных
  страниц и баз сохраняется между запусками. Частично доступные страницы хранятся отдельно от
  полностью прочитанных версий и повторяются; повтор не занимает лимит новых страниц.
- Исчезновение из поисковой выдачи не удаляет локальную запись: search имеет задержки индекса.
  Эта версия хранит ранее импортированные заметки; зеркальное удаление не входит в задачу.
- Вложения, PDF, аудио, изображения и комментарии не загружаются; текст ссылок и названия
  вложений остаются частью страницы. Новые файлы базы и миграция схемы SQLite не требуются.

## Ошибки и ограничения

Запросы ограничиваются скоростью бесплатного тарифа. На 429/529 учитывается `Retry-After`;
число повторов ограничено. Сетевые ошибки, 401 и 403 показываются как ошибки источника
через существующие статус и журнал. HTTP-перенаправления не должны уносить токен на другой host.
Отсутствие или истечение токена даёт понятную инструкцию подключения без вывода секрета.

Платная подписка Notion для чтения не нужна. Существующий лимит блоков бесплатного workspace
ограничивает создание блоков, но чтение остаётся доступным. Пересказ использует текущую модель
Brain и её обычный лимит пачки; настройка `summarize: false` отключает его для Notion.

## Проверка готовности

Тесты на локальном HTTP-сервере и временной SQLite проверяют импорт текста и свойств,
вложенные страницы и строки баз, пагинацию, обновления без дублей, новые страницы со старой датой,
повтор после оборванного прогона, неполный Markdown и ошибки авторизации/лимита без утечки токена.
Проверяется появление источника в общем реестре. Затем запускается полный unittest-набор.
После подключения реального токена: пробный импорт, поиск известного текста и повторный запуск
без новых записей при неизменившемся Notion.
