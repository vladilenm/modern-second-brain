# Источник YouTube: статистика и комментарии своих каналов

Запрос: чтобы нейронки знали, что вышло на каналах пользователя, как это зашло и что пишет аудитория.
Два своих канала. В базу идут видео со статистикой и комментариями зрителей.
Расшифровка речи и чужие просмотренные видео — вне рамок (пользователь их не выбрал).

## Решение

API-коннектор `youtube` на официальном YouTube Data API v3 с ключом. Отвергнут `yt-dlp`:
комментарии он собирает медленно, а YouTube периодически режет такие запросы; фоновой
синхронизации нужен предсказуемый источник. Только стандартный Python, как у остальных коннекторов.

Ключ API лежит в связке ключей macOS (`brain-youtube` / `default`), в `config.json` его нет.
Ключ даёт доступ только к публичным данным; вход в аккаунт YouTube не нужен.

## Настройки

```json
"sources": {"youtube": {
  "enabled": false,
  "channels": ["@handle-первого-канала", "@handle-второго-канала"],
  "every_minutes": 360,
  "comments_per_video": 30,
  "max_videos_per_run": 100,
  "summarize": true
}}
```

Канал задаётся как `@handle`, ссылка на канал или идентификатор `UC…`. Пустой список каналов при
включённом источнике — ошибка источника с подсказкой.

## Запись

Одно видео — одна запись, включая Shorts.

- `source` — `youtube`; `external_id` — идентификатор видео; `location` — ссылка на видео.
- `title` — название видео; `kind` — `discussion` (у пересказа уже есть промпт для обсуждений).
- `project` — пусто: каналы не являются проектами. При желании канал привязывается к проекту
  через `project_aliases` позже, отдельным решением.
- `started_at` и `updated_at` — дата публикации. Обновление статистики дату не двигает, поэтому
  старые видео не всплывают в «Что нового» и не получают прибавку свежести в поиске.
- Текст записи:

```
Канал: <название>
Опубликовано: 2026-10-03 · 18:42
Статистика: около 12 тыс. просмотров · 540 лайков · 87 комментариев

Описание:
<описание видео>

Комментарии зрителей (сначала самые заметные):
— <текст комментария> (лайков: 41)
  ↳ автор канала: <текст ответа>
  ↳ <текст ответа зрителя>
```

- Имена зрителей в запись не попадают: для контекста важен текст, а не автор. Ответы владельца
  канала помечаются «автор канала».
- Числа статистики округляются до двух значащих цифр (12 345 → «около 12 тыс.»): иначе запись
  менялась бы при каждом прогоне и заново уходила на пересказ.
- Комментарии берутся по порядку «релевантности» YouTube, до `comments_per_video` веток,
  к каждой — ответы, которые API отдаёт вместе с веткой (до пяти). Если комментарии отключены,
  запись создаётся без раздела комментариев.
- Номера карт и прочее маскирует общий `redact`, как у всех источников.

## Что и когда обновляется

Каждый прогон:

1. По каждому каналу — список всех загруженных видео (плейлист загрузок) и их статистика. Это дёшево:
   две страницы по 50 видео — два запроса.
2. Очередь на обновление записи (с повторным чтением комментариев):
   - видео, которых ещё нет в курсоре, — от новых к старым;
   - опубликованные меньше 7 дней назад — раз в сутки;
   - от 7 до 90 дней — раз в 7 дней;
   - старше 90 дней — раз в 90 дней.
3. За прогон обновляется не больше `max_videos_per_run` видео; остальные ждут следующего прогона.
   Первый проход по нескольким сотням видео растянется на несколько прогонов.

Курсор — JSON `{"videos": {"<id>": "<дата последнего обновления>"}}`; sync сохраняет его вместе
с записанной пачкой, как у Notion. Видео, удалённые с канала, из базы не удаляются.

Расход квоты: список и статистика — около 25 запросов на 600 видео, комментарии — один запрос на
видео. Первый проход 600 видео — порядка 650 единиц при дневной квоте 10 000.

Расход на пересказ: одна запись на видео при первом проходе, дальше — только изменившиеся записи
по расписанию выше. Общий лимит `llm.batch_limit` на прогон действует как для всех источников.

## Ошибки

- Нет ключа — ошибка источника с командой `security add-generic-password -s brain-youtube -a default -w`.
- Канал не найден — ошибка источника с именем канала; остальные каналы обрабатываются.
- Квота исчерпана (`quotaExceeded`) — прогон останавливается с сохранённым курсором, продолжение
  в следующем прогоне; в статусе — «квота YouTube API исчерпана до завтра».
- Комментарии отключены (`commentsDisabled`) — не ошибка.
- Сеть — как у остальных API-источников: ошибка прогона, повтор через 15 минут.

## Подключение для пользователя

1. Google Cloud Console → проект → включить «YouTube Data API v3» → создать ключ API
   (ограничить его этим API).
2. `security add-generic-password -s brain-youtube -a default -w` — команда сама спросит ключ.
3. В `config.json`: `"youtube": {"enabled": true, "channels": ["@…", "@…"]}`.
4. `bin/brain sync --source youtube --no-summarize` — проверить, затем обычная синхронизация.

## Проверка

Тесты на локальном HTTP-сервере, как у GitHub и Notion: разбор канала по `@handle`, ссылке и `UC…`;
постраничный список видео; сборка текста записи с округлением и ответами автора; отключённые
комментарии; расписание обновления по возрасту видео с фиксированным «сейчас»; лимит на прогон
и продолжение с курсора; исчерпанная квота; отсутствие ключа; неизменность записи при малом
изменении статистики. Реестр источников в существующих тестах дополняется `youtube`.

Ручная проверка: первый прогон на реальных каналах на копии базы, затем на рабочей.

## Вне рамок

Расшифровка речи из видео, аналитика удержания (нужен вход в аккаунт), чужие просмотренные видео,
удаление записей исчезнувших видео, цвет источника в панели сверх существующей палитры.
