# Инструменты MCP: недавнее, проект, фильтры поиска

Запрос: нейронка должна получать контекст без угадывания слов для поиска — спросить,
что было недавно, взять проект целиком, сузить поиск проектом и давностью.
Сбор, пересказ и ранжирование поиска не меняются.

## Решение

Средний набор: новые инструменты `recent` и `project`, два необязательных параметра у `search`.
Отвергнуты один `recent` (контекст проекта по-прежнему собирался бы вручную) и инструмент
записи в базу (первый пишущий инструмент, теряется «только чтение»; отдельный проект).

Все инструменты только читают базу и сохраняют пометку `readOnlyHint`.
Только стандартный Python 3.9, без новых зависимостей.

## Проекты

Правило «папка `~/…/club-landing` и репозиторий `vladilenm/club_landing` — один проект»
(`project_key`) переезжает из `brain/dashboard.py` в новый модуль `brain/projects.py`.
`brain.dashboard.project_key` остаётся как импорт оттуда: панель и её тесты не меняются.

В том же модуле:

- **Список проектов** — по всем записям: ключ, имя (самое частое), сырые значения поля
  `project`, число записей, дата последней записи.
- **Поиск проекта по имени.** Запрос приводится к ключу тем же правилом. Порядок:
  точное совпадение с ключом; иначе точное совпадение с одним из сырых путей; иначе
  проекты, у которых запрос — подстрока ключа, имени или пути. Один кандидат — найден;
  несколько — ответ со списком кандидатов (до 10) и просьбой уточнить; ни одного —
  «проект не найден» и подсказка вызвать `project` без имени.
- Записи без проекта образуют группу «Без проекта»; по имени она не ищется.

## Инструмент `recent`

Параметры: `days` (целое, 1–30, по умолчанию 3), `project` (строка, необязательно),
`source` (как у `search`, необязательно).

Берутся записи с `updated_at` не старше `days` суток. Группировка по проекту и разбор
атомов — как в блоке «Что нового» панели: основные типы `decision`, `todo`, `error`, `fix`
в этом порядке, внутри типа от свежих записей к старым; группы упорядочены по числу
основных знаний, при равенстве по свежести, «Без проекта» последней.

Ответ — текст:

```
Что нового за 3 дня: 18 записей, 6 проектов

## club-landing — 5 записей · 4 решения · 2 задачи · 1 ошибка
- решение: Субтитры вшиваем в ролик через ffmpeg [id 2301]
- задача: Проверить шрифт на телефоне [id 2298, продолжение]
…ещё 3 знания, команды и факты: 7
Без знаний: «Название записи» [id 2290]; …

…ещё 2 проекта: youtube (4 записи), brain (1 запись). Сузь параметром project.
```

- На проект — до 5 основных знаний, остальные одной строкой-счётчиком вместе с числом
  команд и фактов. Записи без знаний — до 3 названий с id.
- Проектов в ответе — до 10; остальные перечислены одной строкой с числом записей.
  Группа «Без проекта» показывается всегда и в счёт десяти не входит.
- Если задан `project`, отдаётся одна группа без обрезки: все шесть типов знаний и все
  записи без знаний.
- Пометка «продолжение» — у записей с `started_at` раньше начала периода: у атомов нет
  своей даты, знания такой записи могли появиться до периода.
- Пусто — «За N дней записей не было» и дата последней записи в базе.

## Инструмент `project`

Параметр: `name` (строка, необязательно).

Без имени — список проектов, свежие сверху, до 50 строк и строка «ещё N»:

```
Проектов: 212, записей без проекта: 1668

club-landing — 143 записи, последняя 2026-11-11
youtube — 58 записей, последняя 2026-11-10
```

С именем — карточка проекта:

```
Проект club-landing
Пути: ~/Documents/vscode/club-landing; vladilenm/club_landing
Записей: 143 (Claude Code 80, Codex 41, GitHub 22) · 2025-12-03 — 2026-11-11

Последние записи:
[id 2301] Название · Codex · 2026-11-11
  Краткое содержание до 300 символов…

Последние решения:
- Субтитры вшиваем в ролик через ffmpeg [id 2301, 2026-11-11]

Последние задачи (статус выполнения в базе не хранится):
- Проверить шрифт на телефоне [id 2298, 2026-11-09]
```

- Последних записей — 10, решений — 10, задач — 10, от свежих к старым.
- Раздел назван «последние задачи», а не «открытые»: признака выполнения в базе нет.
  Оговорка в заголовке раздела обязательна.
- Тем проекта в ответе нет: в панели они считаются по всей базе при сборке.

## Инструмент `search`

Два новых необязательных параметра:

- `project` — имя проекта, ищется так же, как в инструменте `project`. Несколько
  кандидатов или ни одного — ошибка инструмента с тем же текстом, поиск не выполняется.
- `days` — целое от 1: только записи с `updated_at` не старше N суток.

Оба условия добавляются в `WHERE` запроса к индексу, до ранжирования. Формула, веса
колонок, поправка на свежесть и запас кандидатов не меняются. Без новых параметров
SQL-запрос и результаты совпадают с нынешними.

## Инструкция сервера и описания

В `INSTRUCTIONS` добавляется, что вызывать: «что нового», «на чём остановились»,
«чем я занимался» — `recent`; вопрос про конкретный проект или просьба ввести в курс —
`project`; конкретный вопрос — `search` (с `project` и `days`, когда известны);
читать запись целиком — `get_record`. Описание каждого инструмента объясняет то же
со своей стороны. Порядок в `tools/list`: `search`, `get_record`, `recent`, `project`.

## Командная строка

`bin/brain recent [--days N] [--project ИМЯ] [--source ИСТОЧНИК]` и
`bin/brain project [ИМЯ]` печатают тот же текст, что получает нейронка.
`bin/brain search` получает `--project` и `--days`.

## Ошибки

Некорректные параметры (`days` вне диапазона, не число) — ошибка инструмента с понятным
текстом. База не найдена — существующее сообщение. Исключения внутри инструмента —
существующая обёртка «Ошибка: …».

## Проверка

`tests/test_brain.py`, `unittest`:

- `projects`: ключи и объединение папки с репозиторием; точное, по пути и по подстроке
  совпадение; несколько кандидатов; не найдено.
- `recent`: отбор по дням, проекту и источнику; порядок групп и типов; обрезка до 5 знаний
  и до 10 проектов; полный вывод с `project`; пометка «продолжение»; пустой период.
- `project`: список без имени; карточка с путями, источниками, записями, решениями и
  задачами; оговорка про статус задач.
- `search`: без новых параметров результат тот же, что до правки (тот же порядок id на
  фиксированном наборе); `project` и `days` сужают выдачу; неоднозначный проект — ошибка.
- MCP по stdio: четыре инструмента в `tools/list`, все с `readOnlyHint`; вызовы `recent`
  и `project` возвращают текст.
- Панель: существующие тесты `DashboardTests` и `ProjectKeyTests` проходят без правок.

Ручная проверка на реальной базе: `bin/brain recent`, `bin/brain project`,
`bin/brain project club-landing`, `bin/brain search "…" --project … --days 30`;
после перезапуска Claude Code — вызов новых инструментов через MCP.

## Вне рамок

Запись в базу из MCP, статус выполнения задач, темы проекта в MCP, дайджест от модели,
изменение ранжирования поиска.
