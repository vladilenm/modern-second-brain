# Универсальная установка и мастер настройки

Дата: 2026-11-23. Brain делался под одного человека. Теперь его ставят другие люди, в основном управленцы,
которым важно, что данные лежат у них и переживут блокировки сервисов. Сейчас поставить его может только
тот, кто готов читать README на 460 строк, править `config.json` руками и вводить команды `security`.

## Зачем

Новый человек должен за 10 минут пройти путь от «увидел репозиторий» до «нейронка ищет по моей истории».
Для этого нужно четыре вещи:

1. установить одной командой;
2. выбрать источники галочками и настроить каждый без правки файлов;
3. понять, где лежат его данные и что уходит наружу;
4. подключить базу к своим нейронкам и агентам по MCP.

## Что решено

- **Платформа**: только macOS. Хранилище секретов и автозапуск — отдельные модули с одним интерфейсом:
  Linux и Windows потом добавляются новым бэкендом, а не переделкой.
- **Установка**: одна команда `curl -fsSL …/install.sh | sh`. Homebrew и PyPI не делаем.
- **Мастер**: полноэкранный список с галочками на `curses` из стандартной библиотеки. Если терминал
  не справляется, мастер сам переходит на простые вопросы по очереди.
- **Подход A**: каждый коннектор сам описывает свою настройку (поля, секрет, поиск на компьютере, проверку).
  Мастер общий и ничего не знает про конкретные источники. Новый коннектор попадает в мастер сам,
  как сейчас попадает в CLI, MCP и панель.
- **MCP**: мастер ничего не прописывает в конфиги чужих программ. README и итоговый экран мастера дают
  готовые команды и JSON с правильным путём, вставляет их человек сам.
- **Модель пересказа**: в мастере тот же равный список, что в BrainBar (`llm_settings.PROVIDERS`),
  без выделения. Шаг можно пропустить.
- **Значок BrainBar**: отдельный шаг мастера, по умолчанию «нет».
- **Названия** не меняются: команда `brain`, репозиторий `modern-second-brain`.
- Формат `config.json` и имена записей в связке ключей не меняются: существующая установка
  продолжает работать без миграции данных.

## Что отбросили

- Мастер как веб-страница: нужен локальный сервер и передача секретов через браузер, объём вдвое больше.
- Автоматическая правка конфигов Claude Desktop, Cursor и других клиентов: решение пользователя.
- Перенос данных из папки проекта в `~/Library/Application Support`: при установке в `~/brain`
  данные и так в предсказуемом месте, а перенос сломал бы BrainBar и существующие установки.

## Установка: `install.sh`

Файл в корне репозитория. Запуск:

```bash
curl -fsSL https://raw.githubusercontent.com/vladilenm/modern-second-brain/main/install.sh | sh
```

Переменные: `BRAIN_HOME` (куда ставить, по умолчанию `~/brain`), `BRAIN_REF` (ветка, по умолчанию `main`).

Шаги:

1. Не macOS — выход с сообщением «пока только macOS».
2. Нет Command Line Tools (`xcode-select -p` падает) — выход с подсказкой `xcode-select --install`
   и просьбой запустить установку снова. Command Line Tools дают и `/usr/bin/python3`, и `git`.
3. `BRAIN_HOME` внутри `~/Documents`, `~/Desktop` или `~/Downloads` — выход: launchd не пускает туда
   фоновые задачи.
4. Папки нет — `git clone --depth 1 -b $BRAIN_REF` во временную папку рядом и переименование в `BRAIN_HOME` при успехе. Папка есть и это наш репозиторий —
   обновление (`git pull --ff-only`). Папка есть, но чужая — выход, ничего не трогаем.
5. Ссылка `~/.local/bin/brain` → `$BRAIN_HOME/bin/brain`. Если `~/.local/bin` нет в `PATH`, установщик
   спрашивает (через `/dev/tty`), дописать ли строку `export PATH="$HOME/.local/bin:$PATH"` в `~/.zprofile`.
   По умолчанию «да», при отказе печатает строку для ручной вставки.
6. Есть терминал — `exec brain setup </dev/tty`. Нет — печатает «дальше: brain setup».

`bin/brain` сейчас ищет проект через `dirname "$0"`, а через ссылку это `~/.local/bin`. Скрипт будет
разворачивать ссылку (цикл `readlink`, без `-f`: в старом macOS его нет).

`brain update` — то же, что шаг 4 для уже установленного проекта: `git pull --ff-only`, затем, если
автозапуск включён, пересоздаёт его plist. В конце печатает «перезапусти Claude Code/Codex, чтобы
подхватить новые инструменты MCP». `data/`, `config.json` и `inbox/` в git не попадают, их обновление не трогает.

## Описание настройки в коннекторе

В `brain/connectors/base.py` появляется поле настройки и три атрибута класса `Connector`:

```python
@dataclass(frozen=True)
class Field:
    key: str                 # ключ в sources.<name>; у секрета — только имя для показа
    label: str               # «Адрес почты», «Каналы»
    kind: str = "text"       # text | list | secret | int
    help: str = ""           # одна строка под полем
    required: bool = False
    account_from: str = ""   # для secret: поле, значение которого — аккаунт в связке ключей (почта: address)

class Connector:
    setup_fields: Tuple[Field, ...] = ()   # что спросить; пусто — источник включается без вопросов
    setup_help: str = ""                   # где взять ключ или пароль: шаги и ссылки, показывается перед полями

    def detect(self) -> Optional[str]:
        """Что уже есть на компьютере, одной строкой: «412 разговоров», «вход в gh: vladilenm».
        None — ничего не найдено. Быстро, без сети, где можно."""

    def check(self) -> str:
        """Пробное подключение не дольше 20 секунд, без записи в базу. Возвращает строку для показа
        («канал найден: 1 240 видео»), при ошибке бросает RuntimeError с понятной причиной."""
```

Секрет лежит в связке ключей. Его сервис и аккаунт коннектор уже знает (`keychain_service`,
`keychain_account` или адрес почты), мастер их не придумывает.

| Источник | detect | Поля | check |
|---|---|---|---|
| Claude Code, Codex, Kimi | число файлов разговоров в `roots` | — | папки читаются |
| ChatGPT | число архивов в `inbox/` | — (в `setup_help` — как выгрузить экспорт) | папка `inbox/` есть |
| GitHub | `gh` найден и залогинен, под кем | исключить репозитории (list) | `gh auth token` + запрос `/user` |
| Gmail, Яндекс.Почта | — | адрес (text, обяз.), пароль приложения (secret, аккаунт = адрес) | вход по IMAP и выбор ящика |
| Notion | токен уже в связке ключей | токен (secret) | `GET /users/me` |
| YouTube | ключ уже в связке ключей | каналы (list, обяз.), ключ API (secret) | каналы находятся по ключу |
| Telegram | — | каналы (list, обяз.) | страница `t.me/s/<канал>` открывается и в ней есть посты |

Если `gh` не установлен или не залогинен, мастер показывает `brew install gh` / `gh auth login`
и предлагает повторить проверку. Сам вход не запускает.

Технические поля (`roots`, `every_minutes`, `backfill_days`, `max_pages_per_run` и т. п.) мастер не спрашивает:
у них разумные умолчания, они описаны в `docs/sources.md`.

## Мастер: `brain setup [источник]`

Новые модули:

- `brain/ui.py` — интерфейс взаимодействия с двумя реализациями: `CursesUi` (список с галочками,
  стрелки, пробел, Enter) и `TextUi` (вопросы по очереди). Методы: `checklist`, `ask`, `ask_secret`
  (через `getpass`), `confirm`, `choose`, `say`. `TextUi` принимает потоки ввода и вывода — на нём тесты.
- `brain/wizard.py` — шаги мастера. Знает только `Connector`, `Field`, `secret_store`, `autostart`,
  `llm_settings` и `config`.

Шаги `brain setup`:

1. **Источники.** `checklist` со всеми коннекторами из реестра. Рядом с каждым — результат `detect()`
   или короткая подсказка «нужен токен». Изначально отмечены: при первом запуске — найденные `detect()`,
   при повторном — уже включённые в конфиге.
2. **Настройка выбранных.** Для каждого с полями: `setup_help`, затем поля. Текущие значения подставляются
   по умолчанию: Enter оставляет как есть. Если секрет уже есть в связке ключей, мастер спрашивает
   «заменить? [д/Н]». Потом `check()`. При ошибке — причина и выбор «повторить / пропустить источник /
   включить всё равно». Снятые галочки выключают источник (`enabled: false`), его записи в базе остаются.
3. **Модель пересказа.** `choose` из `PROVIDERS` + «свой адрес» + «пропустить». Дальше — модель
   (список с API провайдера, как в BrainBar, или ввод вручную) и ключ (secret). Сохраняет `llm_settings.save`.
   Пояснение одной строкой: без модели поиск идёт по сырому тексту, с моделью текст записей уходит провайдеру.
4. **Автозапуск.** `confirm` «синхронизировать каждые 15 минут в фоне? [Д/н]».
5. **Значок в строке меню.** `confirm` «[д/Н]» → `menubar/build.sh`.
6. **Первая синхронизация.** `confirm` «забрать данные сейчас? [Д/н]» → `brain sync --no-summarize`
   с выводом в терминал. Первый прогон GitHub и почты за 2 года долгий: мастер предупреждает
   и говорит, что прерывание (Ctrl+C) ничего не ломает, автозапуск продолжит.
7. **Итог.** Где лежат данные, что включено, готовые команды MCP с реальным путём к `bin/brain`,
   следующие шаги: `brain search`, `brain dashboard --open`.

`brain setup notion` — только шаг 2 для одного источника (и включает его). Ctrl+C на любом шаге
выходит без записи несохранённого: конфиг пишется после шага 2, после 3 и после 4, каждый раз атомарно.

### Запись конфига

`config.save_sources(changes)` читает сырой `config.json` (без умолчаний), вливает в `sources.<name>`
только то, что спросил мастер, плюс `enabled`, и пишет атомарно с правами 0600 — как уже делает
`llm_settings.save`. Общую часть атомарной записи выносим в `config.write_raw`, и её используют оба.
Остальные ключи (`exclude_projects`, `project_aliases`, личные настройки) не трогаются.

## Секреты: `brain/secret_store.py`

Заменяет `brain/keychain.py`, интерфейс не зависит от ОС. Имя не `secrets.py`, чтобы не путать со стандартным модулем `secrets`:

- `get(service, account, command=None) -> str` — как сейчас `keychain.password`;
- `put(service, account, secret)` — записать или заменить;
- `exists(service, account) -> bool`;
- `add_command(service, account) -> str` — ручная команда для сообщений об ошибке.

Бэкенд macOS — `/usr/bin/security`. `put` передаёт секрет через stdin режима `security -i`
(`add-generic-password -U -s … -a … -w …`), чтобы он не попал в аргументы процесса (`ps`) и в историю.
Если этот путь не сработает при реализации, запасной вариант — `security add-generic-password … -w`
без значения: тогда `security` спрашивает пароль сам, человек вводит его дважды. Коннекторы
переходят с `keychain.password` на `secret_store.get`.

## Автозапуск: `brain/autostart.py`

- `enable()`, `disable()`, `status() -> str` и CLI `brain autostart on|off|status`.
- Бэкенд launchd: plist собирается в коде с реальными путями (`ROOT/bin/brain`, лог
  `~/Library/Logs/brain-sync.log`), метка `local.brain.sync`. Расписание прежнее: :00, :15, :30, :45,
  `Nice 10`, `LowPriorityIO`, `PYTHONUNBUFFERED=1`.
- `enable()` перезаписывает plist и перезагружает агент (`bootout` и `bootstrap`). Если есть агент
  со старой меткой `com.vladilen.brain-sync`, снимает его и удаляет его plist: это наша прежняя метка,
  а не чужой автозапуск.
- Файл `launchd/com.vladilen.brain-sync.plist` из репозитория удаляется.

## Что отвязываем от автора

- `launchd/` с жёсткими `/Users/vladilen` — заменяет `autostart.py`.
- BrainBar: метка агента — `local.brain.sync`, bundle id — `local.brain.brainbar`. Путь к проекту
  `menubar/build.sh` вписывает в `Info.plist` (ключ `BrainDir`), BrainBar читает его оттуда,
  `~/brain` — запасной вариант.
- README: команды MCP через `~/.local/bin/brain` или `$BRAIN_HOME/bin/brain`, без `/Users/vladilen`.
- Примеры в `config.example.json` и комментариях — нейтральные (`owner/repo-*`).
- Тесты с `vladilenm/...` остаются: это данные тестов, а не настройки.

Переход у автора: `git pull`, затем `brain autostart on` (снимет старый агент, поставит новый)
и `menubar/build.sh`. Конфиг и ключи остаются как были.

## Документация

**README.md** — для нового человека, читается за 5 минут:

1. Что это: одна строка и абзац зачем (вся история работы у тебя на диске, не зависит от доступности
   сервисов, нейронки ищут по ней через MCP).
2. Установка: команда curl, что она делает, требования (macOS, Command Line Tools).
3. Настройка: `brain setup`, перенастройка одного источника.
4. Источники: таблица «что берёт / что нужно / ссылка на раздел в docs/sources.md».
5. **Где всё хранится**: база `data/brain.db`, панель `data/dashboard.html`, статус `data/status.json`,
   настройки `config.json`, архивы ChatGPT `inbox/`, секреты в связке ключей (сервисы `brain-mail`,
   `brain-notion`, `brain-youtube`), лог `~/Library/Logs/brain-sync.log`, автозапуск
   `~/Library/LaunchAgents/local.brain.sync.plist`. Резервная копия — скопировать `data/` и `config.json`.
6. **Подключение к нейронкам по MCP**: Claude Code (`claude mcp add -s user brain -- <путь> mcp`), Codex
   (`codex mcp add`), Claude Desktop (JSON для `claude_desktop_config.json`), Cursor (`~/.cursor/mcp.json`),
   любой другой клиент (stdio-команда `<путь> mcp`). Четыре инструмента и что они делают.
   Перезапуск клиента после обновления.
7. **Что с этим делать**: 5–7 примеров запросов агенту («на чём я остановился в проекте X», «как мы
   решили вопрос с вебхуком», «что нового за неделю»), панель, команды терминала.
8. Что уходит наружу: коннекторы только читают свои сервисы; текст записей уходит провайдеру модели,
   только если пересказ включён; больше ничего.
9. Обновление (`brain update`) и удаление (`brain autostart off`, удалить папку, ссылку, записи
   в связке ключей, MCP в клиентах).

**docs/sources.md** — текущие подробные разделы по каждому источнику из README, без изменений по сути,
плюс технические параметры конфига. **docs/development.md** — устройство, новый источник (теперь с
`setup_fields`, `detect`, `check`), тесты, сборка панели и BrainBar, исключённые проекты и правила проектов.

## Ошибки

- `check()` упал — причина и выбор «повторить / пропустить / включить всё равно». Мастер не падает.
- `security` недоступна или отказ доступа к связке ключей — сообщение с ручной командой `add_command`.
- `curses` не работает (нет терминала, слишком маленькое окно, `TERM=dumb`) — переход на `TextUi`.
- `install.sh` при любой ошибке останавливается (`set -eu`) и не оставляет полуготовую папку:
  клонирует во временную рядом и переименовывает в `BRAIN_HOME` только при успехе.
- `launchctl bootstrap` упал — причина и ручная команда, остальной мастер продолжается.

## Тесты

- `wizard.py` на `TextUi` с заготовленным вводом и фальшивыми коннекторами: выбор источников, поля,
  повтор и пропуск после ошибки `check()`, Enter сохраняет текущее значение, отказ от источника выключает его.
- `config.save_sources`: чужие ключи не трогаются, права 0600, запись атомарная.
- `secret_store` с подменой команды `security`: секрет не попадает в аргументы процесса.
- `autostart`: собранный plist с подставленными путями, снятие старой метки (с фальшивым `launchctl`).
- `detect` и `check` каждого коннектора на подставных папках и HTTP-ответах, как в существующих тестах.
- `install.sh`: `shellcheck`, прогон с `BRAIN_HOME` во временной папке и локальным репозиторием как источником:
  установка, повторный запуск (обновление), отказ на чужой папке и на `~/Documents`.
- `bin/brain` через ссылку находит проект.

## Вне рамок

- Linux и Windows (интерфейсы готовы, бэкендов нет).
- Автоматическая правка конфигов MCP-клиентов.
- Homebrew, PyPI, подписанный установщик `.pkg`.
- Новые источники и изменения в самих коннекторах, кроме `detect`/`check`/полей.
