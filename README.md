# Второй мозг

Локальная поисковая база прошлой работы: разговоры с ИИ (Claude Code, Codex, Kimi Code, ChatGPT),
данные GitHub (обсуждения PR и issues, коммиты по месяцам, README), почта (Gmail и Яндекс:
мои переписки и помеченные письма), страницы и записи баз Notion.
Скрипт забирает новое, чистит от служебного шума, складывает в SQLite и ищет через BM25 с поправкой на свежесть.
Claude подключён к базе через MCP.

Только стандартный Python 3.9 (`/usr/bin/python3`), без внешних зависимостей. Из программ — `gh` для GitHub
и `zstd` для сжатых сессий Codex.

## Команды

```bash
bin/brain sync                 # забрать новое и пересказать очередь
bin/brain sync --no-summarize  # только забрать
bin/brain sync --source github # один источник сейчас, без расписания
bin/brain sync --rescan        # забрать всё заново (после правки коннектора)
bin/brain search "ошибка бота клуба" -n 5
bin/brain show 42              # запись целиком (длинные — кусками, --offset)
bin/brain status               # сколько записей, живы ли коннекторы, очередь пересказа
bin/brain summarize --limit 10
bin/brain mcp                  # MCP-сервер (его запускает Claude сам)
```

```

  codex.py          ~/.codex/sessions/**/rollout-*.jsonl и сжатые .jsonl.zst (только разговоры с человеком)
  kimi.py           Kimi Code / CLI и встроенная история Kimi Desktop (только основные разговоры)
  chatgpt_export.py архивы экспорта ChatGPT из папки inbox/
  github.py         GitHub через gh: PR и issues с участием пользователя, коммиты по месяцам, README
  mail.py           почта по IMAP: пароль, пачки, курсор; стратегии gmail.py и yandex_mail.py,
                    разбор писем mailparse.py, слой над imaplib mailbox.py
  notion.py         страницы, вложенные заметки и записи баз через REST API Notion

                    и в нём 30 минут тишины; API-источник — с сохранённого курсора
brain/db.py         SQLite: records + полнотекстовый индекс FTS5 (trigram)

                    вопросы для поиска, ключевые слова, атомы (ошибки, команды, решения)

brain/web/          исходники панели базы (brain dashboard)
```

## Пересказ (нужна модель)

Скопируй `config.example.json` в `config.json` и впиши адрес OpenAI-совместимого API,
ключ и модель. `config.json` в git не попадает. Ключ можно не хранить в файле,
а передавать через переменную `BRAIN_LLM_API_KEY`.

Без модели всё работает, но поиск идёт только по сырому тексту записей.
Первый прогон — около 2 млн токенов на всю историю; дальше понемногу.
За один `sync` пересказывается `llm.batch_limit` записей (по умолчанию 40), свежие первыми.
Записи короче `llm.min_chars` (по умолчанию 300 символов — пустой PR, короткий README) модели
не отправляются: они ищутся по своему тексту. Промпт пересказа зависит от типа записи: разговор,
обсуждение, коммиты, документ.

## Исключённые проекты

Проекты, разговоры из которых в базу не нужны (например, автоматические прогоны бота),
перечисляются в `config.json`:

```json
"exclude_projects": ["~/Documents/dev/tbank-invest"]
```

Подпапки исключаются вместе с проектом. Новые разговоры оттуда `sync` пропускает,
а уже попавшие удаляет из базы и индекса при следующем запуске.

## Codex

Сессии из `~/.codex/sessions` и `~/.codex/archived_sessions`, без ревьюеров (guardian) и порождённых агентов.
Закончившиеся сессии Codex через несколько дней сжимает в `rollout-*.jsonl.zst` — их распаковывает `zstd`
(`brew install zstd`; в Python 3.9 модуля для него нет). Запись при сжатии не меняется, обновляется только путь к файлу.

Правка сообщения в Codex заводит ветку — отдельный файл `rollout-…-<тред>_<ветка>.jsonl`, где лежит только
то, что после правки. Запись собирается по самой новой ветке вместе с началом разговора из прежнего файла;
брошенные ветки в неё не попадают.

## Kimi Code / Kimi CLI

Источник `kimi` включён по умолчанию. Читает `~/.kimi-code/sessions`, старую папку `~/.kimi/sessions`
и встроенный Kimi Code в приложении для macOS:
`~/Library/Application Support/kimi-desktop/daimon-share/daimon/runtime/kimi-code/home/sessions`.

Один разговор — одна запись: вопросы и текст ответов, без рассуждений, вывода инструментов,
системных вставок, подагентов и служебных сессий генерации заголовков. Журнал `wire.jsonl`
сохраняет историю до сжатия контекста; для старых сессий без журнала читается `context.jsonl`.
Проект берётся из `state.json`, индекса сессий или старого `kimi.json`. Действуют общие
`exclude_projects` и ожидание 30 минут тишины.

```bash
bin/brain sync --source kimi --no-summarize
bin/brain search "запрос" --source kimi
```

Если история перенесена через `KIMI_CODE_HOME` / `KIMI_SHARE_DIR`, задай фактическую папку
`sessions` в `config.json` (список заменяет стандартные пути):

```json
"sources": {"kimi": {"enabled": true, "roots": ["~/my-kimi/sessions"], "idle_minutes": 30}}
```

Форматы хранения: [Kimi Code](https://moonshotai.github.io/kimi-code/en/configuration/data-locations.html),
[старый Kimi CLI](https://moonshotai.github.io/kimi-cli/en/configuration/data-locations.html).

## ChatGPT

API для чтения истории у OpenAI нет. ChatGPT → Settings → Data controls → Export data,
архив из письма положить в `inbox/`. Следующий `sync` добавит новые и изменившиеся чаты.

## GitHub

Токен берётся у `gh` (`gh auth login`, если ещё не залогинен) — отдельных ключей не нужно.
Источник запускается раз в час (`every_minutes`), первый раз забирает 2 года (`backfill_days`), дальше — только новое.
Если прогон упал (например, нет сети, пока Mac спит), повтор — в следующем sync, через 15 минут.

- обсуждения: PR и issues, где пользователь автор, участник или упомянут, — с комментариями и ревью;
- коммиты пользователя по месяцам: одна запись на репозиторий и месяц, при новом коммите пересобирается только текущий месяц;
- README каждого репозитория, в который пушили, с описанием и темами.

Форки пропускаются. Исключить репозитории — шаблоны в `config.json`, уже попавшие записи удалятся при следующем `sync`:

```json
"sources": {"github": {"exclude_repos": ["vladilenm/tbank-*"]}}
```

`brain sync --source github` — забрать сейчас, без расписания; `brain sync --rescan --source github` — заново за 2 года.

## Почта

Gmail и Яндекс.Почта по IMAP. В базу идут только мои переписки (треды, где есть моё письмо) и треды
с помеченным письмом; за 2 года, дальше — каждые 15 минут новое. Одна запись — один тред: письма по порядку,
цитаты прошлых писем и подписи срезаны, от вложений — только имена. Номера банковских карт маскируются.

Подключение:

1. Пароль приложения.
   - Gmail: myaccount.google.com/apppasswords (нужна двухэтапная аутентификация).
   - Яндекс: Яндекс ID → «Безопасность» → «Пароли приложений» → «Почта»; в настройках почты
     «Почтовые программы» включить IMAP и пароли приложений.
2. Положить пароль в связку ключей — команда сама его спросит, в историю терминала он не попадёт:

   ```bash
   security add-generic-password -s brain-mail -a ты@gmail.com -w
   ```

3. В `config.json` включить ящик:

   ```json
   "sources": {"gmail": {"enabled": true, "address": "ты@gmail.com"}}
   ```

Яндекс отдаёт заголовки по IMAP медленно и не умеет искать по ним, поэтому треды собираются по своему
индексу заголовков (таблица `mail_index`): каждый заголовок читается один раз, по 5 минут за прогон.
Первый проход ящика за 2 года растягивается на несколько прогонов; пока он идёт, в статусе может мелькать
«Яндекс.Почта: ошибка IMAP (… problems with connection)» — Яндекс рвёт долгие сессии, прочитанное не теряется.
Письма, которые Яндекс по IMAP не отдаёт (с флагом `encrypted`), пропускаются.

Не пересказывать ящик моделью — `"summarize": false` в его секции: письма будут искаться по своему тексту.
Пароль в связке ключей поменять — `security delete-generic-password -s brain-mail -a <адрес>` и добавить заново.

## Notion

Источник `notion` читает весь доступный токену workspace: страницы, вложенные заметки и строки баз,
включая обычные разделы «Личное» и «Архив». Одна страница — одна запись со ссылкой на оригинал,
текстовыми свойствами и содержимым Markdown. Только чтение, без скачивания файлов и комментариев.
Платная подписка Notion для API-чтения не нужна.

1. Создай [персональный API-токен](https://www.notion.so/developers/tokens) с возможностью **Notion API**.
   Workers не нужен. На Free создавать такие токены может владелец workspace. Токен действует с правами
   пользователя; код Brain только читает страницы. Альтернатива — внутренняя интеграция с правом
   **Read content**, которой нужно открыть корневые страницы через **Connections → Add connection**.
2. Сохрани токен в связке ключей macOS; команда спросит значение, не записывая его в историю:

   ```bash
   security add-generic-password -U -s brain-notion -a default -w
   ```

3. Включи источник в `config.json`:

   ```json
   "sources": {"notion": {"enabled": true, "every_minutes": 15, "summarize": true}}
   ```

```bash
bin/brain sync --source notion --no-summarize
bin/brain search "текст заметки" --source notion
```

Первый импорт забирает до 100 новых или изменённых страниц за запуск (`max_pages_per_run`),
следующий продолжает по сохранённой очереди. Тела неизменившихся страниц не скачиваются;
позже открытая доступу старая заметка тоже импортируется. Поиск Notion имеет задержку индексации,
поэтому коннектор дополнительно обходит вложенные страницы и запрашивает строки найденных баз.
`--rescan --source notion` заново читает доступные страницы; дубли отсекаются по хешу.
Удалённые и закрытые страницы сохраняются в локальной базе как ранее импортированные заметки.
Временные подписи ссылок на вложения Notion убираются из индексируемого текста: обновление
ссылки не считается правкой заметки и не запускает новый пересказ. Сам файл открывается
через оригинальную страницу Notion.

Токен не хранится в config.json. При его истечении положи новый той же командой в связку ключей.
Для другого workspace можно задать отдельный `keychain_account` вместо `default`.
`"summarize": false` оставляет поиск по оригинальному тексту без отправки страниц модели.

Документация: [токены и Free](https://developers.notion.com/guides/get-started/personal-access-tokens),
[Markdown API](https://developers.notion.com/reference/retrieve-page-markdown),
[ограничения поиска](https://developers.notion.com/reference/search-optimizations-and-limitations).

## Новый источник

1. Файл в `brain/connectors/`:
   - файлы на диске — класс от `FileConnector` с методами `files()` и `parse(path) -> [Record]`;
   - источник за API — класс от `ApiConnector` с методом `fetch(cursor)`, который отдаёт `Batch(records, cursor)`.
     Курсор — строка в любом формате, её хранит sync и сдвигает вместе с записанной пачкой.
2. У класса — `name` (ключ в config), `source` (ключ записей), `title` и `about` (как показывать людям и Claude).
3. Строка в `ALL` в `brain/connectors/__init__.py` и секция в `sources` в `brain/config.py`.

Курсор, дубли, индекс, расписание, пересказ и свежесть — общие. Списки источников в CLI, MCP, панели
и значке строятся из реестра сами.

## MCP

Подключён для всех проектов Claude Code и в Codex:

```bash
claude mcp add -s user brain -- /Users/vladilen/brain/bin/brain mcp
claude mcp remove brain -s user   # отключить в Claude Code
codex mcp add brain -- /Users/vladilen/brain/bin/brain mcp
codex mcp remove brain            # отключить в Codex
```

Оба инструмента помечены как «только чтение» (`readOnlyHint`), поэтому Codex вызывает их
без запроса разрешения.

## Автозапуск

`brain sync` через launchd по часам — в :00, :15, :30 и :45 (если Mac спал, пропущенный запуск
выполнится при пробуждении), лог — `~/Library/Logs/brain-sync.log`. Не `StartInterval` и не
`ProcessType: Background`: с ними macOS откладывала запуски на десятки минут.
Проект лежит в `~/brain`, а не в «Документах»: macOS не пускает фоновые задачи launchd
в защищённые папки (Документы, Рабочий стол, Загрузки) — там агент падает с «Operation not permitted».

```bash
cp launchd/com.vladilen.brain-sync.plist ~/Library/LaunchAgents/
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.vladilen.brain-sync.plist   # включить
launchctl bootout gui/$(id -u)/com.vladilen.brain-sync                                    # выключить
rm ~/Library/LaunchAgents/com.vladilen.brain-sync.plist                                   # убрать совсем
launchctl kickstart gui/$(id -u)/com.vladilen.brain-sync                                  # прогнать сейчас
```

## Значок в строке меню

`~/Applications/BrainBar.app` — мозг в строке меню. Каждые 2 секунды читает `data/status.json`,
который пишут `brain sync` и `brain summarize`:

- без подписи — всё синхронизировано;
- `↻` — забирает новое из источников;
- `12/40` — пересказывает 12-ю запись из 40;
- `!` — прогон упал или прервался, либо синхронизации не было больше 45 минут;
- `?` — синхронизация ещё ни разу не запускалась.

Вверху меню — состояние базы, общее число записей и время запусков. «Открыть базу» (`⌘O`),
«Синхронизировать сейчас» (`⌘R`) и последние карточки доступны сразу. В подменю «Источники» —
таблица записей и готовых карточек; в «Настройках» — модель, автозапуск, журнал и папка проекта.
Во время работы обновляется прогресс, повторный запуск недоступен. Ошибки отдельных источников
тоже отмечаются в значке; при ошибке журнал можно открыть прямо из главного меню.
Выход из BrainBar не останавливает фоновую синхронизацию.

«Настройки → Модель и провайдер…» (`⌘,`) показывает, кто обрабатывает заметки, и позволяет
выбрать SimpleClaw, OpenRouter, OpenAI, Ollama или другой OpenAI-совместимый API.
Список моделей загружается у выбранного провайдера; название также можно ввести вручную.
Для API без поддержки `response_format: json_object` отключи запрос JSON.
После сохранения выбор применяется к следующему запуску. Текущий прогон продолжает использовать
прежнюю модель, а готовые карточки не пересоздаются. Если модели различаются, меню показывает оба выбора.

Ключи и последние выбранные модели сохраняются отдельно для каждого адреса API в локальном
`config.json` (права `0600`, файл исключён из Git). Пустое поле ключа сохраняет уже записанный ключ
этого провайдера. Ключ из `BRAIN_LLM_API_KEY` остаётся привязан к исходному профилю и не переносится
на новый адрес; явно введённый ключ имеет приоритет для выбранного профиля.
`bin/brain model show` выводит настройки без секретов. Окно также открывается при повторном запуске BrainBar.

```bash
menubar/build.sh                                            # собрать, установить, перезапустить
menubar/build.sh --build-only                               # только сборка, без установки
~/Applications/BrainBar.app/Contents/MacOS/BrainBar --dump  # текст меню без интерфейса
```

## Панель базы

`bin/brain dashboard --open` (или «Открыть базу» в значке) собирает `data/dashboard.html` и открывает
в браузере. Слева меню с поиском (клавиша `/`) и состоянием синхронизации, у каждой вкладки свой адрес:

- **Обзор** (`#overview`) — записей, проектов, знаний из карточек, доля карточек; записи по неделям
  по источникам (3 месяца, год, всё время); проекты с наибольшим числом записей; свежие записи.
- **Граф** (`#graph`, `#graph/<id>`, `#graph/p:<ключ>`) — записи вокруг своих проектов и связи между
  похожими записями. Похожесть считается при сборке (`brain/topics.py`): ключевые слова карточек сводятся
  к основе («рилс», «рилса» — одна тема), даты, числа, файлы и пути выкидываются, сходство — косинус
  с весом idf, у каждой записи до 3 своих соседей. Граф объёмный: Three.js и `3d-force-graph`,
  физика `d3-force-3d`, камера OrbitControls, подписи `three-spritetext`. Проект из двух записей
  и больше — крупная сфера с оболочкой; вокруг него располагаются записи цвета своего источника.
  Подписи смотрят на камеру, мелкие узлы остаются различимыми при отдалении.
  - Клик выбирает запись или проект: справа панель с пересказом, темами и похожими записями (у проекта —
    связанные проекты и последние записи), её связи выделяются, остальные остаются фоном.
    Серые линии соединяют записи с проектами, фиолетовые — записи с общими темами. Второй клик открывает
    карточку или страницу проекта. «Только связанные» раскладывает заново одну окрестность: запись,
    её похожие и их похожие.
  - Фильтры по источнику и периоду; поиск подсвечивает совпадения, Enter перелетает к следующему.
  - «Вид»: связи по темам и порог их силы, объёмные области проектов, сколько подписей, разложить заново.
  - Кнопка в углу графа или `F` разворачивают его вместе с фильтрами на весь экран; `Esc` или та же кнопка
    сворачивают. Где браузер так не умеет (iPhone), граф растягивается поверх страницы.
  - Перетаскивание фона вращает камеру, правая кнопка сдвигает; колесо или щипок меняет масштаб.
    На сенсорном экране один палец вращает, два — сдвигают и приближают. Клавиши: `+` `−` `0`,
    стрелки, `Esc` снимает выбор, `Enter` открывает выбранное.
  - Раскладка по трём координатам и настройки вида запоминаются в браузере. Скрытая вкладка
    приостанавливает WebGL; системное уменьшение движения отключает перелёты и видимую симуляцию.
    Если WebGL недоступен, открывается прежний 2D-граф.
- **Проекты** (`#projects`, `#project/<ключ>`) — карточки проектов; на странице проекта — решения и задачи
  из карточек и все записи по месяцам. Папка и репозиторий с одним именем (`~/…/club-landing` и
  `vladilenm/club_landing`) — один проект.
- **Записи** (`#records`) — здоровье источников (синхронизация, ошибки, ещё идут, пропущено) и все записи
  по дням с фильтрами.

По клику на запись — карточка: пересказ, похожие записи, атомы, начало расшифровки, переход на граф.
Это снимок на момент сборки: данные вшиты в страницу, сервер и внешние скрипты не нужны. Исходники страницы —
`brain/web/` (`index.html`, `style.css`, `charts.js`, `graph.js`, `graph-3d.js`, `app.js`),
сборка склеивает их и локальный `graph-vendor.js` в один файл.
В файле то же, что в базе, поэтому он в `data/` (в git не попадает) с правами 600.

Готовый `graph-vendor.js` хранится в репозитории: Node.js не нужен для `brain dashboard`.
Для обновления библиотек: в `brain/web` выполнить `npm ci` и `npm run build`.
Версии закреплены в `package-lock.json`, лицензии — в `graph-vendor.LICENSE.txt`.
`npm run test:graph` проверяет граф в отдельном Chrome на искусственных данных без внешних запросов
(нужны Node.js, Python 3 и установленный Google Chrome; канал можно задать через `BROWSER_CHANNEL`).

## Как это работает

Ни Docker, ни сервера базы нет. База — один файл SQLite `data/brain.db`, его читает и пишет тот,
кому он нужен в данный момент:

- `brain sync` раз в 15 минут запускает launchd: процесс забирает новое, пересказывает очередь и завершается;
- MCP-сервер `brain` запускает сам Claude, когда открывается сессия, и закрывает вместе с ней;
- BrainBar — маленькое приложение в строке меню: читает `data/status.json`, запускает команды
  и сохраняет выбор модели через `brain model`.
